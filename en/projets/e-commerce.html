Context and goal

I wanted to test products on small European markets, quickly, and in a language I do not always speak. AI agents can write a complete theme in a few hours; the risk is no longer knowing what is live, or how to roll back. So the goal was twofold: move fast, and stay in control of every change published.

Delegate the writing, not the publishing

I set working rules for the agents, written down in the project notes:

  • Nothing goes live without my approval, and only one file at a time, so the shop's settings are never overwritten.
  • A restore point before touching the live theme: a full copy of the theme (627 files for the bracelet shop), then a before/after log per file, with the rollback command.
  • Nothing non-public in the files served: backups and notes are kept outside the theme.
  • Credentials, bank details and identity: me alone. The agent never enters them.

What testing caught

The fixes were coded by the agent and validated by me on the live site. Some defects came from my own tests, others from the audits carried out before launch.

  • Broken images on the Dutch version. The translation tool was also translating file names stored in text settings: an image called “step” became “stap”, and no longer existed. Those settings became non-translatable lists, and the rule is now written down: a setting that contains a file name is never a free-text field.
  • A forced switch back to English. While testing, I found that choosing Dutch changed nothing: automatic language detection sent visitors back to English right after they chose. The fix: a language explicitly present in the URL is never overridden.
  • A cart that reloaded the page. Changing the colour of an item triggered a server error (400), then a full reload. The call targeted the variant instead of the cart line; it is fixed, and the cart now updates without reloading.
  • Personal data on a legal page. The auto-generated privacy policy reinserted a personal email address and postal address every time it was saved. It was switched to a written version, with no personal data.

What I take away from it

Having an agent write the code does not remove the work, it moves it: less typing, more specification, verification and traceability. It is the lesson from my internship, applied to a different field: the time saved on writing is reinvested in testing.

I also keep a very concrete rule from it: an automated tool processes everything you hand it, including things that should never have gone through it. The translated file names proved it.
